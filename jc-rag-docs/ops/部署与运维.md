## 二、部署前置条件

### 2.1 硬件
- CPU：4 核及以上
- 内存：16 GB 及以上（Milvus 独立 4 GB，ES 独立 2 GB）
- 磁盘：100 GB 及以上可用空间（向量索引 + 文档 + 模型）

### 2.2 软件
- Docker Desktop / Docker Engine 24+
- Docker Compose v2
- JDK 17
- Maven 3.9+
- Python 3.10 / 3.11
- Node.js 20+
- Ollama 0.5+（[https://ollama.com](https://ollama.com)）

### 2.3 模型准备
```powershell
# 拉取 LLM
ollama pull qwen2.5:7b

# 拉取 Embedding（bge-large-zh-v1.5）
ollama pull bge-large-zh-v1.5
```

## 三、启动顺序

> 严格按顺序启动：基础设施 → 模型 → Python RAG → Java 后端 → 前端。

### 3.1 启动基础设施（docker-compose）

```powershell
cd D:\Project\jc-rag
docker compose up -d
```

**校验**：
```powershell
docker compose ps
# 期望：mysql / elasticsearch / redis / minio / etcd / standalone 全部 healthy 或 running
```

### 3.2 初始化数据库与 ES 索引

```powershell
# MySQL 初始化（首次部署）
Get-Content docs\sql\mysql\001_jc_rag_all_in_one.sql | docker exec -i rag-mysql mysql -uroot -proot123456

# Elasticsearch 索引初始化
# 用 VS Code REST Client 打开 docs/es/001_jc_rag_all_in_one.http，逐条执行
```

### 3.3 启动 Ollama
```powershell
# 已配置为系统服务时直接启动；否则
ollama serve
# → http://localhost:11434
```

**校验**：
```powershell
curl http://localhost:11434/api/tags
# 期望返回已拉取的模型列表
```

### 3.4 启动 Python RAG 服务
```powershell
cd D:\Project\jc-rag\backend-python
python -m venv .venv
.\.venv\Scripts\activate
pip install -r requirements.txt
python main.py
# → http://localhost:8001/docs
```

**校验**：
```powershell
curl http://localhost:8001/api/v1/health
# 期望：{"status":"ok"}
```

### 3.5 启动 Java 后端
```powershell
# 管理端（正式入口）
cd D:\Project\jc-rag\server
mvn -pl jc-rag-admin -am spring-boot:run
# → http://localhost:8080

# C 端（新终端）
cd D:\Project\jc-rag\server
mvn -pl jc-rag-user -am spring-boot:run
# → http://localhost:8082
```

**校验**：
```powershell
curl http://localhost:8080/api/sys/health
curl http://localhost:8082/api/health
```

### 3.6 启动前端
```powershell
# 管理端
cd D:\Project\jc-rag\frontend\jc-rag-admin-web
npm install
npm run dev
# → http://localhost:5173

# C 端（新终端）
cd D:\Project\jc-rag\frontend\jc-rag-user-web
npm install
npm run dev
# → http://localhost:5175
```

## 八、数据备份

### 8.1 MySQL 备份
```bash
# 完整备份
docker exec mysql sh -c 'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" --all-databases' > backup/mysql-$(date +%Y%m%d).sql

# 单库备份
docker exec mysql sh -c 'mysqldump -u root -p"$MYSQL_ROOT_PASSWORD" jc_rag' > backup/jc_rag-$(date +%Y%m%d).sql

# 恢复
docker exec -i mysql sh -c 'mysql -u root -p"$MYSQL_ROOT_PASSWORD"' < backup/jc_rag-20260629.sql
```

### 8.2 Milvus 备份
```bash
# Milvus 数据在 volume: milvus_data
# 备份整个 volume
docker run --rm \
    -v milvus_data:/source:ro \
    -v $(pwd)/backup:/backup \
    alpine tar czf /backup/milvus-$(date +%Y%m%d).tar.gz -C /source .

# 恢复
docker run --rm \
    -v milvus_data:/target \
    -v $(pwd)/backup:/backup \
    alpine tar xzf /backup/milvus-20260629.tar.gz -C /target
```

### 8.3 MinIO 备份
```bash
# 用 mc 客户端
mc alias set local http://localhost:9000 minioadmin minioadmin
mc mirror local/jc-rag-bucket backup/minio-$(date +%Y%m%d)/
```

### 8.4 Elasticsearch 备份
```bash
# 注册仓库
curl -X PUT "localhost:9200/_snapshot/backup" -H 'Content-Type: application/json' -d'{
  "type": "fs",
  "settings": { "location": "/usr/share/elasticsearch/backup" }
}'

# 快照
curl -X PUT "localhost:9200/_snapshot/backup/snapshot-$(date +%Y%m%d)?wait_for_completion=true"
```

### 8.5 备份策略

| 数据 | 频率 | 保留 |
|---|---|---|
| MySQL | 每天 03:00 全量 | 30 天 |
| Milvus | 每周日全量 | 4 周 |
| MinIO | 每天增量 | 90 天 |
| ES | 每周日全量 | 4 周 |

### 8.6 备份脚本
`jc-rag-pro-script/backup-all.sh`（自动跑 cron）：
```bash
#!/bin/bash
set -e
BACKUP_DIR=/backup/$(date +%Y%m%d)
mkdir -p $BACKUP_DIR

# MySQL
docker exec mysql sh -c 'mysqldump -uroot -p"$MYSQL_ROOT_PASSWORD" --all-databases' > $BACKUP_DIR/mysql.sql

# Milvus
docker run --rm -v milvus_data:/source:ro -v $BACKUP_DIR:/backup alpine tar czf /backup/milvus.tar.gz -C /source .

# 压缩
tar czf $BACKUP_DIR.tar.gz $BACKUP_DIR
rm -rf $BACKUP_DIR

# 上传到 OSS（如配置）
# aliyun oss cp $BACKUP_DIR.tar.gz oss://jc-rag-backup/

# 清理 30 天前
find /backup -name "*.tar.gz" -mtime +30 -delete
```

## 十、故障处理

### 10.1 故障分类

| 等级 | 含义 | 响应时间 |
|---|---|---|
| P0 | 核心服务全挂 | 立即 (5 分钟) |
| P1 | 商业版不可用 | 30 分钟 |
| P2 | 部分功能异常 | 2 小时 |
| P3 | 性能/UI 问题 | 1 天 |

### 10.2 常见故障

#### F1: Java 启动失败
```bash
# 1. 看日志
docker logs jc-rag-app-admin

# 2. 常见原因
# - 数据库连接失败 → 检查 mysql 状态
# - 端口占用 → netstat -ano | findstr 8080
# - License 失效 → 重新生成

# 3. 解决
docker compose -f docker-compose.pro.yml restart jc-rag-app-admin
```

#### F2: License 验签失败
```
错误: "License verification failed" / "LICENSE_INVALID"
原因:
  1. License 过期 → 用 gen-license.sh 重新生成
  2. License 文件被改 → 从备份恢复
  3. License 与公钥不匹配 → 重新生成
```

#### F3: Milvus 连接失败
```bash
# 1. 检查 milvus 状态
docker logs milvus-standalone

# 2. 常见原因
# - etcd 未起 → 启 etcd
# - 磁盘满 → df -h
# - OOM → 加内存

# 3. 重启 milvus
docker compose restart milvus-standalone
```

#### F4: MySQL 连接数爆满
```sql
-- 查看连接
SHOW PROCESSLIST;
-- 杀空闲连接
KILL <ID>;
-- 调 max_connections
SET GLOBAL max_connections = 500;
```

#### F5: ES 集群 Yellow/Red
```bash
# Yellow: 单节点正常, 多节点副本未分配
curl -X PUT "localhost:9200/_cluster/settings" -H 'Content-Type: application/json' -d'{
  "transient": {"cluster.routing.allocation.enable": "all"}
}'

# Red: 索引损坏, 需从备份恢复
```

#### F6: Python 服务 OOM
```bash
# 1. 看进程
docker stats jc-rag-python-pro

# 2. 加内存 (docker-compose.pro.yml)
services:
  jc-rag-python-pro:
    deploy:
      resources:
        limits:
          memory: 4G
```

### 10.3 故障应急群
- 微信群：`jc-rag-ops`
- OnCall 轮值：见 `jc-rag-pro-docs/operations/oncall-rotation.md`
- 升级流程：P0 → 5 分钟无响应 → 打电话给 Tech Lead

### 10.4 常见问题

#### ES 启动后 status: red
- 单节点部署默认 `yellow`；`red` 表示数据损坏或磁盘满
- 检查 `es_data` 卷磁盘空间

#### Milvus standalone 健康检查超时
- 首次启动依赖 etcd 与 minio，需等待 1~3 分钟
- 查看日志：`docker logs rag-milvus`

#### Python RAG 启动报 `pydantic` 版本冲突
- 务必使用项目自带 `requirements.txt` 锁定的版本
- 不要混用全局 Python 环境

#### Java 后端启动报端口占用
- 检查 8080/8082 是否被占用：`netstat -ano | findstr :8080`
- 修改 `application.yml` 的 `server.port` 后重启

#### 前端 npm install 失败
- 切换国内镜像：`npm config set registry https://registry.npmmirror.com`
- 删除 `node_modules` 与 `package-lock.json` 后重试

### 11.2 关键告警规则
```yaml
# alertmanager/rules.yml
groups:
- name: jc-rag
  rules:
  - alert: ServiceDown
    expr: up{job="jc-rag-admin"} == 0
    for: 1m
    severity: P0

  - alert: HighMemory
    expr: container_memory_usage_bytes > 4 * 1024 * 1024 * 1024
    for: 5m
    severity: P2

  - alert: SlowApi
    expr: http_request_duration_seconds{quantile="0.95"} > 1
    for: 5m
    severity: P2

  - alert: LicenseExpiringSoon
    expr: license_days_remaining < 7
    severity: P1
```

```bash
# 2. 恢复 MySQL
docker compose up -d mysql
sleep 30
docker exec -i mysql sh -c 'mysql -uroot -p"$MYSQL_ROOT_PASSWORD"' < backup/mysql-20260629.sql

# 3. 恢复 Milvus（见 8.2）

# 4. 启所有服务
docker compose -f docker-compose.pro.yml up -d
```

### 12.3 服务被攻击应急
```bash
# 1. 隔离
docker network disconnect jc-rag-net jc-rag-app-admin

# 2. 看攻击源
docker logs jc-rag-app-admin | grep -i "attack\|flood\|sql.injection"

# 3. 加白名单 (nginx)
# 修改 nginx.conf, 限制 IP

# 4. 重启
docker compose -f docker-compose.pro.yml restart nginx
```

## 十三、License 管理（仅商业版）

### 13.1 License 生成
```bash
# 给客户生成 License
bash jc-rag-pro-script/gen-license.sh \
    -c "JC-Customer-001" \
    -e "2027-12-31" \
    -o jc-rag-pro-enterprise/jc-rag-pro-app-admin/src/main/resources/LICENSE-KEY
```

### 13.2 License 校验
启动时自动校验：
- 校验失败 → 日志记录 + 商业版功能禁用
- 校验成功 → 启动正常

### 13.3 License 续期
```bash
# 生成新 License
bash jc-rag-pro-script/gen-license.sh \
    -c "JC-Customer-001" \
    -e "2028-12-31" \
    -o LICENSE-KEY-new

# 替换客户服务器的 LICENSE-KEY
scp LICENSE-KEY-new customer@server:/path/to/LICENSE-KEY

# 重启服务
ssh customer@server "docker compose restart jc-rag-app-admin"
```

### 13.4 License 吊销
```bash
# 在客户服务器上删除 License
ssh customer@server "rm /path/to/LICENSE-KEY"
ssh customer@server "docker compose restart jc-rag-app-admin"
# 启动后商业版功能自动失效
```

## 十四、生产环境建议

- 所有中间件使用独立服务器或 K8s Pod，避免与 Java/Python 应用混部
- Ollama 建议独立部署，AI 推理独占 GPU
- MySQL 开启 binlog + 每日全量备份
- ES 与 Milvus 数据卷启用快照备份
- 前端使用 Nginx 反向代理 + HTTPS
- 关闭外网，仅保留内网访问
