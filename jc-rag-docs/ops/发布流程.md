# 发布流程（开源版 + 商业版 + 生产部署）

> 覆盖三件事：版本号规范、双版本发布步骤、回滚，以及本地打包到生产（etc）的部署操作。

---

## 一、版本号规范

| 类型 | 格式 | 示例 | 同步关系 |
|---|---|---|---|
| **开源版** | `MAJOR.MINOR.PATCH` | `0.1.0` | 公开仓统一版本号 |
| **商业版** | `MAJOR.MINOR.PATCH-pro.N` | `0.1.0-pro.1` | 跟开源版 `MAJOR.MINOR.PATCH`，`-pro.N` 商业版小版本 |
| **内部模块** | maven 习惯 | `0.1.0-SNAPSHOT` | 跟整体一致 |

**示例时间线**：
- community v0.1.0 → pro v0.1.0-pro.1
- community v0.2.0 → pro v0.2.0-pro.1（同步开源版升级）
- community v0.2.0 → pro v0.2.0-pro.2（商业版小功能）

---

## 二、开源版发布流程 (community)

### 2.1 前置条件
- [ ] 所有功能已 PR 合入
- [ ] 测试通过：`mvn test` + `pytest`
- [ ] 文档已更新（CHANGELOG.md + README.md）
- [ ] SQL 脚本已归档到 `docs/sql/mysql/`

### 2.2 发布步骤

#### Step 1: 升级版本号
```bash
# 修改 jc-rag-community/jc-rag-frontend/jc-rag-admin-web/package.json
# 修改 jc-rag-community/jc-rag-frontend/jc-rag-user-web/package.json
# 修改 jc-rag-community/jc-rag-backend/pom.xml <version>
# 修改 jc-rag-community/jc-rag-service/pyproject.toml version
```

#### Step 2: 跑测试
```bash
# Java
mvn -pl jc-rag-community/jc-rag-backend -am clean test

# Python
cd jc-rag-community/jc-rag-service
python -m pytest

# 前端
cd jc-rag-community/jc-rag-frontend/jc-rag-admin-web
npm run test
```

#### Step 3: 打包
```bash
# Java 端 (输出 jar)
mvn -pl jc-rag-community/jc-rag-backend -am clean package -DskipTests

# Python 端 (打 wheel)
cd jc-rag-community/jc-rag-service
python -m build

# 前端 (输出 dist)
cd jc-rag-community/jc-rag-frontend/jc-rag-admin-web
npm run build
```

#### Step 4: 打 tag
```bash
git add .
git commit -m "release: community v0.1.0"
git tag -a v0.1.0 -m "community v0.1.0"
git push origin master
git push origin v0.1.0
```

#### Step 5: 部署到公开仓（v1.0 之后）
```bash
# 假设 community 公开仓已建
bash jc-rag-pro-script/extract-community.sh
# 见 docs/edition/migration-guide.md
```

#### Step 6: 写 CHANGELOG
```bash
# 追加到 CHANGELOG.md
cat >> CHANGELOG.md << EOF
## [0.1.0] - $(date +%Y-%m-%d)
### Added
- ...
### Fixed
- ...
EOF
```

### 2.3 发布物清单

```
jc-rag-community/
├─ jc-rag-backend/
│  ├─ jc-rag-admin/target/jc-rag-admin.jar
│  ├─ jc-rag-user/target/jc-rag-user.jar
│  └─ ...
├─ jc-rag-service/
│  └─ dist/jc_rag_service-0.1.0-py3-none-any.whl
├─ jc-rag-frontend/
│  ├─ jc-rag-admin-web/dist/
│  └─ jc-rag-user-web/dist/
```

## 三、商业版发布流程 (pro)

### 3.1 前置条件
- [ ] 依赖的 community 版本已发布（如 pro v0.1.0-pro.1 依赖 community v0.1.0）
- [ ] 所有商业功能已实现并测试
- [ ] License 文件已生成（用 `gen-license.sh`）
- [ ] 一键构建脚本跑通：`bash jc-rag-pro-script/build-pro.sh`

### 3.2 发布步骤

#### Step 1: 同步开源版代码
```bash
# 把 community 最新代码同步到 pro 仓
bash jc-rag-pro-script/sync-community.sh
# (v1.0 之后从 community 公开仓拉; 现在是同仓内同步)
```

#### Step 2: 升级商业版版本号
```bash
# 修改 jc-rag-pro-core/jc-rag-pro-backend/jc-rag-pro/pom.xml
# 修改 jc-rag-pro-core/jc-rag-pro-service/pyproject.toml
# 修改 jc-rag-pro-core/jc-rag-pro-frontend/package.json
# 格式: 0.1.0-pro.1
```

#### Step 3: 生成 License
```bash
# 给客户生成 License
bash jc-rag-pro-script/gen-license.sh \
    -c "JC-Customer-001" \
    -e "2027-12-31" \
    -o jc-rag-pro-enterprise/jc-rag-pro-app-admin/src/main/resources/LICENSE-KEY
```

#### Step 4: 一键构建
```bash
bash jc-rag-pro-script/build-pro.sh
# 内部步骤:
#   1. 合并 pro 路由到 jc-rag 前端
#   2. npm run build (jc-rag 模式 pro)
#   3. mvn clean package (pro jar)
#   4. python -m build (pro wheel)
#   5. 复制前端 dist 到 pro jar 的 static/
#   6. 输出 dist/ 目录
```

#### Step 5: 验证
```bash
# 起 jc-rag 服务（开发态）
cd jc-rag
docker compose -f docker-compose.yml up -d  # 基础服务 + jc-rag Python
mvn -pl jc-rag-backend -am spring-boot:run  # jc-rag Java

# 起 pro 服务
cd jc-rag-pro-enterprise
mvn -pl jc-rag-pro-app-admin spring-boot:run -Dspring-boot.run.profiles=pro

# 浏览器验证
# http://localhost:8080/swagger-ui.html
# http://localhost:8080/admin  (商业版管理后台)
```

#### Step 6: 打 tag
```bash
git add .
git commit -m "release: pro v0.1.0-pro.1"
git tag -a v0.1.0-pro.1 -m "pro v0.1.0-pro.1"
git push origin master
git push origin v0.1.0-pro.1
```

### 3.3 发布物清单（交付给客户）

```
pro-release-v0.1.0-pro.1/
├─ admin/                              ← 商业版管理后台
│  ├─ jc-rag-pro-app-admin.jar
│  └─ config/
│     ├─ application.yml
│     ├─ application-pro.yml
│     └─ LICENSE-KEY                   ← ★ 客户 License
│
├─ user/                               ← 商业版用户端
│  ├─ jc-rag-pro-app-user.jar
│  └─ config/
│     └─ LICENSE-KEY
│
├─ python/                             ← 商业版 Python
│  ├─ jc_rag_pro_service-0.1.0-pro.1.whl
│  ├─ docker/Dockerfile
│  └─ rag_config.yml
│
├─ docker-compose.yml                  ← 商业版完整编排
```

## 四、双版本同步规则

| 场景 | 同步动作 | 频率 |
|---|---|---|
| community 修复 bug | pro 同步合入 | 紧急 24h, 普通 1 周 |
| community 新功能 | pro 评估是否需要 | 按 release 周期 |
| pro 新功能 | **不同步**到 community | 商业特性独立 |
| community API 变更 | pro 必须跟进 | 同步发布 |

## 五、回滚流程

### 5.1 开源版回滚
```bash
git tag -d v0.1.0
git push origin :refs/tags/v0.1.0
# 通知所有 community 用户升级到 v0.1.1
```

### 5.2 商业版回滚
```bash
git tag -d v0.1.0-pro.1
git push origin :refs/tags/v0.1.0-pro.1
# 给客户发新版 jar
```

### 5.3 单个模块回滚
```bash
# 比如 jc-rag-admin 出问题, 但 jc-rag-user 正常
git revert <bad-commit>
git tag -a v0.1.1 -m "hotfix jc-rag-admin"
```

## 八、生产环境（etc）部署操作

> 适用于把本地 Windows 环境的开发成果发布到生产 Linux/Windows 服务器。
> 生产环境使用 `application-etc.yml` 配置。

### 8.1 发布物清单

#### 管理端（jc-rag-admin）
```
jc-rag-admin/
├── jc-rag-admin.jar
└── config/
    ├── application.yml
    ├── application-dev.yml
    └── application-etc.yml
```

#### 用户端（jc-rag-user）
```
jc-rag-user/
├── jc-rag-user.jar
└── config/
    ├── application.yml
    ├── application-dev.yml
    └── application-etc.yml
```

#### Python RAG 服务
```
rag-service/
├── app/
├── main.py
├── rag_config.yml
├── requirements.txt
└── .env
```

> 前端 `npm run build` 会自动输出到对应后端 `src/main/resources/static/`，打包 jar 时已包含。

### 8.2 本地发布（一键脚本）

#### 1. 准备
- 确认本地代码已提交/保存
- 确认桌面存在 `rag_release` 文件夹（脚本会自动创建）

#### 2. 执行本地打包

```powershell
# 在项目根目录 d:\Project\jc-rag 下执行
.\scripts\release-local.ps1
```

脚本会自动完成：
1. 构建前端 1：`web\jc-rag-admin-web` → 输出到 `server\jc-rag-admin\src\main\resources\static`
2. 构建前端 2：`web\jc-rag-user-web` → 输出到 `server\jc-rag-user\src\main\resources\static`
3. install 公共模块 `jc-rag-common`（保证下游模块能找到新字段）
4. 打包 jar 1：`server\jc-rag-admin` → `target\*.jar`
5. 打包 jar 2：`server\jc-rag-user` → `target\*.jar`
6. 收集 Python 服务必要文件
7. 收集 Spring 配置（`config/` 目录，含 dev/etc profile）
8. **拷贝到桌面 `rag_release\`**，结构如下：
   - `rag_release\jc-rag-admin\jc-rag-admin.jar`
   - `rag_release\jc-rag-admin\config\` (含 application.yml/dev/etc)
   - `rag_release\jc-rag-user\jc-rag-user.jar`
   - `rag_release\jc-rag-user\config\` (含 application.yml/dev/etc)
   - `rag_release\rag-service\` (Python 完整目录)
   - `rag_release\release-info.txt`（版本时间戳）

### 8.3 服务器部署

#### 1. 上传文件
把桌面 `rag_release\` 整个目录上传到服务器，例如 `/opt/rag_release/`。

#### 2. 执行部署脚本
```bash
# 在服务器上、rag_release 同级目录执行
# 或指定路径：./scripts/release-server.sh /opt/rag_release /opt/rag
./scripts/release-server.sh
```

脚本会自动完成：
1. 停止现有 Java 服务（`jc-rag-admin`、`jc-rag-user`）
2. 停止现有 Python RAG 服务
3. 备份旧 jar 到 `backup/`（带时间戳）
4. 拷贝新 jar 到部署目录
5. 拷贝新 `config/` 覆盖部署目录
6. 同步新 `rag-service/` 代码（不动 venv、data）
7. 启动 Java 服务（带 `--spring.profiles.active=etc`）
8. 启动 Python RAG 服务
9. 健康检查（10s 等待后探测）

#### 3. 服务器环境变量（etc profile 必需）
服务器需预先设置以下环境变量（写入 `/etc/profile.d/rag.sh`）：
```bash
export DB_HOST=10.1.2.3
export DB_PORT=3306
export DB_USER=jc_rag
export DB_PASSWORD=your_db_password
export REDIS_HOST=10.1.2.4
export REDIS_PORT=6379
export REDIS_PASSWORD=
export PYTHON_RAG_URL=http://127.0.0.1:8001
export MINIO_ENDPOINT=http://10.1.2.6:9000
export MINIO_ACCESS_KEY=minioadmin
export MINIO_SECRET_KEY=minioadmin_secret
export MINIO_BUCKET=jc-rag-docs
export ES_URL=http://10.1.2.7:9200
```

`source /etc/profile.d/rag.sh` 后再启动服务。

### 8.4 回滚
服务器脚本每次部署前自动备份到 `backup/jc-rag-admin-YYYYMMDD-HHmmss.jar`。
回滚命令：
```bash
# 停服
./scripts/stop-all.sh

# 恢复（按需修改时间戳）
cp backup/jc-rag-admin-20260101-120000.jar /opt/rag/server/jc-rag-admin.jar
cp backup/jc-rag-user-20260101-120000.jar /opt/rag/user/jc-rag-user.jar

# 启动
./scripts/start-all.sh --profile etc
```

### 8.5 目录约定（脚本假设）

| 用途 | Windows 本地路径 | Linux 服务器路径（默认） |
|---|---|---|
| 项目根 | `d:\Project\jc-rag` | `/opt/rag` |
| 后台 jar 部署 | - | `/opt/rag/server/` |
| 用户 jar 部署 | - | `/opt/rag/user/` |
| Python 服务 | - | `/opt/rag/rag-service/` |
| Spring 配置 | - | 跟随 jar 同目录 `config/` |
| 桌面发布包 | `%USERPROFILE%\Desktop\rag_release` | - |
