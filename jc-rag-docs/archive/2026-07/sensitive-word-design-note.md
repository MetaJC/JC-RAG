# 敏感词管理设计归档

> 来源：根目录 `调整关键词落库管理(新增 Admin 端敏感词管理页).md`，已整理归档。

## 历史背景

该文档记录了一次围绕“敏感词落库、Admin 管理页、安全审计、用户智能体安全防护”的讨论与阶段性设计。

## 归档保留的核心结论

1. 敏感词应落库管理，不应长期维护在 yml 中
2. Admin 端需要独立的敏感词管理页和审计闭环
3. 运行时应采用内存加载与高效匹配算法，避免请求时频繁查库
4. 安全审计、PII 脱敏、用户输入输出过滤需要整体设计

## 当前使用原则

- 现行实现与正式接口请以代码和版本化数据库脚本为准
- 历史讨论稿仅供回溯设计背景，不作为当前事实文档
